Retry retrieval once.

Today’s win: give rejected evidence one more retrieval attempt, with a clear stopping rule.

Recall from memory

Which function stores evidence_ok, and which function chooses the next node? Did Case A’s fallback repair retrieval?

Check your answer

check_evidence stores the decision; choose_next chooses the destination. Fallback prevented generation from using the irrelevant passage, but retrieval’s fault remained.

1 · Add a way back

Our document question stays fixed: “How long does standard shipping take?” In Lesson 7, rejected evidence immediately led to fallback. Now the router can send the workflow back to retrieve.

START → retrieve → check_evidence
          ↑          ├─ accepted → generate → END
          └──────────┤─ rejected, attempts < 2
                     └─ rejected, attempts ≥ 2 → fallback → END

A conditional edge chooses the next node from the current state; choosing an earlier node creates a loop. See the official conditional edges guide. Our stopping rule permits two retrieval attempts total: the first attempt plus one retry.

2 · Count retrievals in state

Open the Python example. Input state starts with attempts: 0. Each retrieval returns the previous count plus one, along with its passage and source. The router reads that updated count after the evidence check.

MAX_ATTEMPTS = 2

def choose_next(state: State) -> Literal["generate", "retrieve", "fallback"]:
    if state["evidence_ok"]:
        return "generate"
    if state["attempts"] < MAX_ATTEMPTS:
        return "retrieve"
    return "fallback"

Check acceptance first: useful evidence on the final allowed attempt should still reach generation. The limit stops another retrieval when evidence fails.

3 · Follow Case A’s state

  1. Before retrieval: state contains the question, case: "a", and attempts: 0.
  2. First retrieval: state now has attempts: 1 and the returns passage with its source.
  3. First check: evidence_ok: False. The router sees 1 < 2 and chooses retrieve.
  4. Second retrieval: attempts: 2. The shipping passage and shipping source replace the earlier values; the question stays unchanged.
  5. Second check: the check replaces its earlier decision and reason. Now evidence_ok: True, so the router chooses generate.

With the default state update behavior used here, returning an existing field replaces its value; omitted fields remain. See the official reducer guide. Every new retrieval goes through the check before routing, so the old decision does not choose the new passage’s path.

A retry needs a chance to find different evidence.

This example simulates an alternative document on Case A’s second retrieval. Repeating an unchanged deterministic search would return the same result. No model or search service runs here. We carry forward Lesson 7’s rule accepting “takes” or “arrives”; it remains a narrow phrase check.

5 · Change the budget

Change MAX_ATTEMPTS = 2 to MAX_ATTEMPTS = 1. Predict A, B, and C again, then rerun all three. Keep the acceptance check first.

Check after your edit

A now takes fallback after its first rejected passage; it never reaches the shipping document. B still generates after one retrieval. C takes fallback after one retrieval. A smaller budget can stop a potentially useful retry.
