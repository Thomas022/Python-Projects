1 · Meet your project

The project README describes this first version. Its supported questions are cost and receipt. Warranty and shipping insurance receive a refusal. This is a small, working foundation for your final assistant.

final-project/
  app.py                 ← the graph you built
  document_search.py     ← passage loading and retrieval
  documents/             ← the shop’s evidence
  cases.json             ← saved evaluation inputs and references
  evaluate.py            ← checks the application’s results

The application reads documents. The evaluator reads cases and calls the application. The application never reads the reference answers. This keeps the evidence used to answer separate from the expectations used to judge the answer. Compare this with the official offline evaluation guide.

question → load_documents → retrieve → check_evidence
accepted → prepare_generation → generate → check_answer
valid → release · invalid → reject_answer
unaccepted evidence → fallback

No new graph concepts today. You are assembling the workflow you already understand into an application. LangGraph’s overview explains its role in orchestrating workflows.

2 · Run your assistant

From your learn project directory, run:

.venv-langgraph/bin/python final-project/app.py cost
.venv-langgraph/bin/python final-project/app.py receipt
.venv-langgraph/bin/python final-project/app.py "shipping insurance"
.venv-langgraph/bin/python final-project/evaluate.py

Expect a cited $5 cost answer, a cited receipt requirement, an evidence_rejected insurance refusal, and 7/7 passing cases. These runs use fixture drafts and make no Gemini calls. The graph’s retrieval, checks, and routing still run.

Your existing root .env loads automatically. With tracing enabled, look for shop-assistant-good-cost or shop-evaluation-good-cost in LangSmith. Graph state is uploaded even in fixture mode. For local-only fixtures, set LANGSMITH_TRACING=false; terminal exports take precedence.

3 · Make the answer follow the evidence

  1. Open the project shipping policy. Change only $5 to $7. Keep the blank line between paragraphs.
  2. Run .venv-langgraph/bin/python final-project/app.py cost again. Record the price and inspect its source label.
  3. Restore $5, rerun cost, then rerun final-project/evaluate.py using the Python command above.

Edit the documents inside final-project/; earlier lesson documents have their own copies.

Check after trying

The edited run releases $7 with shipping.txt#paragraph-2. Retrieval loads the updated passage, the fixture quotes it, and check_answer compares the draft with it. Restoring $5 restores the original answer and the 7/7 baseline.

A valid answer for one run and a PASS against a saved reference are different checks. If you run the evaluator while the price is $7, the fixed $5 reference disagrees. The wrong_price fixture also targets the original $5, so it no longer injects its intended error. Restore $5 before recording the baseline. In Lesson 26, we’ll use failed cases and traces to diagnose behavior.

4 · Optional live draft

.venv-langgraph/bin/python final-project/app.py cost --mode live

This explicitly calls Gemini using your existing key and model setting. Keep billing disabled and stay within free-tier quota. The same strict quotation and citation checks apply: a correct paraphrase may still be rejected. Live mode sends the question and selected passage to Gemini. The baseline suite measures fixture behavior, not live-model reliability.
