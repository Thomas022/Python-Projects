LangGraph + LangSmith · Lesson 05 · 10 minutes

Find the first wrong step.

Today’s win: use the evidence inside a run to distinguish a retrieval problem from a generation problem.

Recall from memory

You changed a shipping passage in lesson 4. Which changed first: retrieval’s input, retrieval’s output, or generation’s output?

Check your answer

Retrieval’s output changed first. The question in retrieval’s input stayed the same. LangGraph applied the updated passage to state, generation received it as input, and generation’s output changed.

1 · A wrong answer can start in different places

For the question “How long does shipping take?”, our example’s shipping document says 3 to 5 business days. A returns passage about 21 days does not answer that question.

  1. Check retrieval’s output against the question. Did retrieval select evidence that answers it? If it selected the returns policy, the first visible problem is retrieval.
  2. Compare retrieval’s output with generation’s input. Did the same passage reach generation? This is the boundary you inspected in lesson 3.
  3. Check generation’s output against its input. If generation received the shipping passage but answered 21 business days, the first visible problem is generation.

A source label alone does not prove an answer is supported. Read the cited passage and compare its claim with the answer.

2 · Run three cases

The new Python example deliberately creates two faulty runs and one correct run. It keeps the same two-node graph. These are controlled examples with fixed passages and simulated generation; no model or search service is called. The values are independent of your edits to lesson 4.

.venv-langgraph/bin/python lessons/0005-find-the-first-wrong-step.py a
.venv-langgraph/bin/python lessons/0005-find-the-first-wrong-step.py b
.venv-langgraph/bin/python lessons/0005-find-the-first-wrong-step.py c

For each case, write down the selected passage, the final answer, and where you think the first problem appears. Use the terminal output first, then check the trace if tracing is enabled.

3 · Inspect the node boundary in LangSmith

Use lesson 3’s tracing setup in the same terminal, then run the three commands again. The runs are named lesson-05-case-a, lesson-05-case-b, and lesson-05-case-c. This sends the example’s question, passages, and answers to your LangSmith workspace.

Open a run’s Details view and inspect retrieve output, generate input, and generate output. LangSmith’s trace viewer lets you inspect the recorded run. Official tracing guide.

In all three cases, the passage should travel correctly between nodes. Passing information successfully does not guarantee that retrieval selected useful information or that generation used it correctly.

4 · Diagnose before checking

Case A retrieves returns evidence and quotes it. Where is the first problem?

Case B receives shipping evidence but answers 21 business days. Where is the first problem?

Check case C after inspecting it

Retrieval returns the shipping passage, generation receives it, and the answer quotes 3 to 5 business days with the shipping source. These checks reveal no problem in this example.

5 · Repair one case

Open the Python file. In generate, remove the case B special branch (the if line and its indented return). Keep the final return that quotes the passage. Predict the result, then rerun case B. The answer should now say 3 to 5 business days. If tracing is enabled, compare the old and new case B runs.

When finished tracing, use LANGSMITH_TRACING=false in the project’s .env file in that terminal, as in lesson 3.
