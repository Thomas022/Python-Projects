LangGraph + LangSmith · Lesson 14 · 10 minutes

Tell the retry what to fix

Today’s win: pass a useful correction from check_answer to the next generate call.

Quick recall

Does answer_ok=False tell you what is wrong with a draft?

Check

No. It records a decision. A separate feedback field can describe the correction.

1 · Decision versus feedback

Lesson 13 retried the right node. Now we give that node information about its mistake. The router still reads answer_ok; the generator reads repair_feedback.

check_answer rejects $50
  → answer_ok = False
  → repair_feedback = "Replace the draft with this exact evidence and citation: ...$5..."
  → generate reads that feedback
  → check_answer checks the replacement draft

This is a deterministic local simulation with no model call. In a model-based version, you would include the accepted evidence and checker feedback in the retry prompt. Feedback can help; the new draft still needs checking.

2 · Predict, run, compare

Open the Python example. Good starts correct. Repair writes $50 until feedback is available, then uses the accepted passage. Stuck deliberately ignores feedback and keeps writing $50.

Retrieval reminder

All three modes retrieve twice, just as in Lesson 13: the first passage gives duration, which fails the cost check; the second gives the $5 cost. Retrying generation adds no retrieval calls.

3 · Follow the state in repair

  1. Before generation: passage says $5; repair_feedback is empty; generation_attempts is 0.
  2. First generate: draft says $50; generation_attempts becomes 1. Passage stays $5.
  3. First check_answer: answer_ok becomes False; repair_feedback contains the required $5 passage and citation.
  4. Second generate: reads feedback, writes the $5 draft, and sets generation_attempts to 2. The earlier feedback remains until the checker updates it.
  5. Second check_answer: accepts the draft and clears repair_feedback. The router chooses release even though the attempt limit has been reached.

The checker clears feedback on acceptance so a fixed error is no longer described as needing repair. Stuck still reaches reject_answer after two drafts: feedback does not remove the retry limit.
