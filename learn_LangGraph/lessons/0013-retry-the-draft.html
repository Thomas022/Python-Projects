Retry the draft, keep the evidence

Today’s win: give a rejected draft one more generation attempt without retrieving the same accepted evidence again.

Quick recall

Generate writes a $50 draft. Which field still contains the $5 evidence?

Check

passage. The Boolean decision belongs to answer_ok, a separate field.

1 · Choose what needs another attempt

In Lesson 12, a rejected draft ended the run. Now we allow one generation retry. Evidence that answers the question is already in state: generation can use it again.

Rejected evidence → retrieve again (existing retrieval limit)
Rejected draft    → generate again (new generation limit)
Accepted draft    → release
Two rejected drafts → reject_answer

Open the Python example. It keeps the two-retrieval limit and adds generation_attempts with MAX_GENERATIONS = 2. Two total generation attempts means one initial draft and one retry.

2 · Read the new routing rule

def choose_answer(state):
    if state["answer_ok"]:
        return "release"
    if state["generation_attempts"] < MAX_GENERATIONS:
        return "generate"
    return "reject_answer"

Check acceptance first. A correct second draft should still be released even though it uses the last allowed attempt. The conditional edge after check_answer can now route back to generate.

What makes the retry different?

This is a local simulation, with no model call. In repair, generate deliberately writes $50 on its first attempt and copies the correct $5 passage on its second. In stuck, it writes $50 both times. A retry limit prevents endless repetition; it does not guarantee improvement.

Check the paths after running

Every mode retrieves twice: first duration, then cost. Good generates once and releases $5. Repair generates $50, rejects it, generates $5, and releases it. Stuck generates $50 twice, then reaches reject_answer with a refusal.

4 · Follow the repair state

  1. Before the first draft: attempts is 2; generation_attempts is 0; passage says $5.
  2. First generate: generation_attempts becomes 1; draft says $50; passage stays $5. Generate resets answer_ok to False while its new draft awaits checking.
  3. First check_answer: answer_ok is False. The router returns generate because one generation attempt remains.
  4. Second generate: generation_attempts becomes 2; the $5 draft replaces the $50 draft. Passage stays $5, and retrieval attempts stays 2.
  5. Second check_answer: answer_ok becomes True. Release copies the current draft into answer.

The new generate call replaces draft rather than building a draft history. The earlier $50 draft is visible in the execution log. During generation, answer_ok False means the draft is not yet accepted; check_answer makes the decision afterward.
