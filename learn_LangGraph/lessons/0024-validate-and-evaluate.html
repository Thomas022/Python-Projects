1 · Add the release boundary

load_documents → retrieve → check_evidence
accepted → prepare_generation → generate → check_answer
answer accepted → release → END
answer rejected → reject_answer → END
evidence rejected → fallback → END

In the Python example, check_answer checks the draft’s claim and citation. A conditional edge uses answer_ok to decide whether release can copy the draft into answer. Official guide: conditional edges.

To make this first validator easy to inspect, we use a narrow output contract: copy the accepted passage sentence, then append its exact source label. The checker tolerates differences in case, whitespace, and trailing sentence punctuation. It rejects paraphrases and extra claims. This is suitable for our quote-based exercise; it is not a general factuality checker.

answer_ok = citation_ok and claim_ok

The citation must be exactly the one from the retrieved hit, appearing once. After removing it, the remaining sentence must match the passage under the normalization above. The price comes from the loaded passage, so $50 does not pass merely because it includes the correct citation.

2 · Practice without using model quota

Keep the original documents with the shipping price restored to $5. Start with these three runs:

.venv-langgraph/bin/python lessons/0024-validate-and-evaluate.py cost --mode good
.venv-langgraph/bin/python lessons/0024-validate-and-evaluate.py cost --mode wrong_price
.venv-langgraph/bin/python lessons/0024-validate-and-evaluate.py cost --mode wrong_source

These modes use fixture drafts: controlled examples, not Gemini outputs. File loading, retrieval, both checks, routing, and release are real. There are no Gemini calls. Predict which check fails before reading the output.

Check after running

good: claim=True, citation=True → released. wrong_price: claim=False, citation=True → draft_rejected. wrong_source: claim=True, citation=False → draft_rejected. The last two keep the draft visible for diagnosis but publish a refusal in answer.

3 · Evaluate the complete runs

Now run all seven saved cases, each with fresh state:

.venv-langgraph/bin/python lessons/0024-validate-and-evaluate.py --suite

The suite adds receipt, an extra unsupported claim, warranty, and insurance. It compares actual status with fixed expected status. For released cases it also compares the actual answer with a fixed reference answer; for rejected cases it checks that a refusal is returned instead of the draft.

This evaluator runs outside the graph. check_answer protects one run; the suite checks behavior across examples. A rejected draft is a PASS when rejection was expected. The evaluator follows the input/output comparison idea described in the official code evaluator guide, but this suite prints local results rather than creating a LangSmith evaluation experiment.

Check the suite result

7/7 PASS: good cost and receipt are released, all three faulty drafts are rejected, and warranty/insurance are rejected before generation.

4 · Test whether your evaluator catches a mistake

In check_answer, temporarily replace 'answer_ok': citation_ok and claim_ok with 'answer_ok': citation_ok. Predict what will fail, then rerun --suite. Restore the original line and run it again.

Check after the experiment

The weakened checker releases wrong_price and extra_claim because both retain the correct citation. Their actual status disagrees with the expected rejection, giving 5/7 PASS. Restoring the claim check brings the suite back to 7/7.

5 · Optional: validate a real Gemini draft

.venv-langgraph/bin/python lessons/0024-validate-and-evaluate.py cost --mode live

This mode reuses GEMINI_API_KEY and GEMINI_MODEL from your saved .env; the default model is gemini-3.5-flash-lite. Keep billing disabled and stay within your free-tier quota. The prompt asks the model to quote the evidence sentence and source. A paraphrase can be rejected even if it is factually correct: that is a known limit of this strict exercise.

Live mode sends the question and selected evidence to Gemini. With LangSmith tracing enabled, fixture and live modes also upload graph state to your workspace. Find lesson-24-live-cost (or the named fixture run), then compare generate output → check_answer input → check_answer output → release or reject_answer. Set LANGSMITH_TRACING=false in .env for local-only fixture practice. Existing terminal exports take precedence.

Setup on another computer

Keep document_search.py and documents/ beside this script. Install into your project environment:

python3 -m venv .venv-langgraph
.venv-langgraph/bin/python -m pip install langgraph langsmith python-dotenv google-genai

No Gemini key is needed for fixture modes. Live mode loads it automatically from the project-root .env. For errors, use Lesson 23’s troubleshooting guide.
