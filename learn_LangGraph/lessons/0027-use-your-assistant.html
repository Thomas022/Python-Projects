LangGraph + LangSmith · Lesson 27 · Final project · 10 minutes

Use your assistant through an interface.

Today’s win: ask several questions in one terminal session while keeping all the checks you built.

Before you start

Finish Lesson 26’s investigation first. Its diagnostic runner intentionally gives 4/5; your unchanged baseline should give 7/7. Creating this lesson does not mark that investigation complete.

1 · Start the terminal chat

From the learn directory, run:

.venv-langgraph/bin/python final-project/chat.py

You’ll see You:. Type one question at a time and press Enter. Use the supported short forms cost and receipt. This first version still refuses other question forms. Type /help for help and /quit to finish.

Default mode uses fixtures, so this practice makes no Gemini calls. Your saved root .env still controls tracing. Enabled LangSmith tracing uploads graph state; terminal exports take precedence.

2 · The interface calls your existing graph

Open chat.py. Its answer_question function calls the compiled graph with fresh input, then the interface prints result['answer'] and its status.

result = graph.invoke({'question': question, 'mode': mode})
print(result['answer'])

This is the same graph execution API described in the official Graph API guide. The interface adds an input loop and presents the final result; retrieval, evidence checks, generation, and validation remain in app.py.

You → question + mode → existing graph → final answer → You

Display answer, not draft. A rejected draft can remain in diagnostic state, but the graph puts a refusal in answer. Printing draft instead would show text that failed your release checks.

Each question starts with a new dictionary. This is repeated single-question use: the assistant does not remember earlier questions. A follow-up such as “what about that?” has no conversation history to resolve it.

3 · Try a mixed session

Restore your project shipping price to $5. In the chat, enter these lines in order:

cost
shipping insurance
receipt
warranty
cost
/quit

Record the statuses below. After the unsupported insurance question, receipt should still work. After warranty, cost should still return the $5 answer with shipping.txt#paragraph-2. No previous question’s passage or draft is supplied to the next run.

For a trace, find a recent shop-chat-good run in LangSmith and inspect its question input. The shared name identifies this interface; each graph invocation is a separate run. Use what you learned in Lesson 26 to explain one refusal.

4 · Optional: use Gemini through the interface

.venv-langgraph/bin/python final-project/chat.py --live

This session explicitly uses Gemini for accepted questions, with your existing key and model configuration. Keep billing disabled and use free-tier quota. The graph rejects unsupported evidence before generation. Live prompts send the question and accepted passage to Gemini. A correct paraphrase can still fail the strict quotation contract.

Setup, API, and connection problems display a message and return to the input prompt without publishing a draft. You can quit at any time. These handling paths do not guarantee that every provider failure is recoverable.

5 · Check the project before finishing

Quit the chat, then run:

.venv-langgraph/bin/python final-project/evaluate.py

Expect 7/7 baseline cases passing. The baseline checks the graph; your mixed session also checks that the interface can present several independent results. Passing fixtures do not prove general factuality or live-model reliability.

Your first project is assembled.

You now have document loading, source labels, retrieval, evidence checks, optional Gemini generation, draft validation, reference evaluation, trace diagnosis, and a terminal interface. Completing Lessons 26 and 27 demonstrates the remaining skills in this course.

This version supports two short question forms over a tiny fictional corpus. Broader questions, paraphrase validation, and a web interface are possible future extensions. They are not extra prerequisites for finishing this project.
