1 · Move evidence into files

Open shipping.txt and returns.txt. These are real, editable text files containing fictional shop policies. Our loader reads each .txt file and splits it at blank lines. Each paragraph becomes a passage.

A passage has text and a source label. The label shipping.txt#paragraph-2 means the second paragraph in that file. This is the same text-plus-metadata pattern used by document loaders. Official knowledge-base tutorial: loading and splitting documents.

2 · Predict, then run

Count the paragraphs before running. How many passages should appear?

.venv-langgraph/bin/python lessons/0019-load-real-documents.py

Open the entry script and shared loader. Read load_passages: it sorts filenames, reads UTF-8 text, splits paragraphs, then keeps each paragraph’s filename and number.

3 · Change the evidence

In shipping.txt, change $5 to $7, save, and run again. The second shipping passage should now say $7 with the same source label. Restore $5 afterward so later lessons’ expected results remain valid.

Check after trying

There are four passages: two in returns.txt, then two in shipping.txt. Editing a price updates the loaded text. No Python code change is needed.

Paragraph labels are simple locators, not permanent IDs: inserting a paragraph renumbers later labels. This loader is for small plain-text examples; PDFs need a loader that preserves page metadata.

This script only reads local files; it does not invoke LangGraph or upload traces.

Setup on another computer

From the project root, create a Python environment and install:

python3 -m venv .venv-langgraph
.venv-langgraph/bin/python -m pip install langgraph python-dotenv

Keep document_search.py and documents/ beside the lesson scripts. Save your LangSmith key once in the project-root .env if tracing is wanted. Every entry script loads that path automatically. Existing terminal exports take precedence. Use LANGSMITH_TRACING=false in .env for local practice only.
