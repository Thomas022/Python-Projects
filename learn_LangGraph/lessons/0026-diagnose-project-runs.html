Find the cause in the trace.

Today’s win: explain an evaluation result using evidence from your assistant’s actual node inputs and outputs.

Recall

Your Lesson 25 answer separated a valid run from a passing reference comparison. If a draft is rejected, must its evaluation fail?

Check your recall

No. Rejection is a PASS when rejection was expected. A released answer can fail when it disagrees with the reference.

1 · Confirm the baseline, then investigate

Restore the price in your project policy to $5. From the learn directory, run:

.venv-langgraph/bin/python final-project/evaluate.py
.venv-langgraph/bin/python lessons/0026-diagnose-project-runs.py

The baseline should pass 7/7. The diagnostic runner uses the same application graph and evaluator. It runs four rejection cases plus one deliberately stale reference. It prints the node updates, expected result, actual result, and evaluation.

For the last case only, the runner copies the good cost case in memory and sets its reference to $7. The document remains $5. It does not edit your policy, application, or cases.json. Expect 4/5 diagnostic cases passing and exit code 1: this is an intentional evaluation failure to investigate.

All five runs use fixture drafts. There are no Gemini calls, no new dependencies, and no new credentials to paste. Your project-root .env loads automatically.

2 · Inspect the same runs in LangSmith

Use your existing saved tracing configuration: LANGSMITH_TRACING=true, your LangSmith key, and your chosen project. Existing terminal exports take precedence over .env. Tracing uploads graph state; use these fictional documents. Open LangSmith, go to Tracing in the workspace/project receiving your runs, and find these run names:

lesson-26-cost-wrong_price
lesson-26-cost-wrong_source
lesson-26-warranty-good
lesson-26-shipping-insurance-good
lesson-26-stale-reference

Open a run and expand its node tree. If your UI offers a Details tab, use it to inspect individual steps and their inputs/outputs. This follows the official trace walkthrough. Fixture runs have a generate node but no Gemini model call inside it.

The expected status and answer also appear in run metadata. The PASS/FAIL calculation happens locally after the graph completes; this runner does not create a LangSmith evaluation experiment or upload evaluation feedback.

If you cannot find a run

Refresh and check the run-name search, time range, workspace, and project. Confirm tracing is enabled; an existing terminal setting can override the saved .env. Check terminal tracing messages for authentication or connection issues without sharing your key. The terminal node updates let you practice the same comparisons locally, but do not establish that a trace was uploaded.

3 · Compare neighboring steps

  1. retrieve output: did it return a hit? Read its text and source.
  2. check_evidence output: was that hit accepted for this question? Read evidence_ok and reason.
  3. generate output: if generation ran, compare draft with the accepted hit.
  4. check_answer output: read answer_ok and answer_reason, then follow release or reject_answer.
  5. Final output versus reference: if the answer was released, compare its exact text with the expected answer printed by the runner.
Follow the $50 draft

1. retrieve returns the $5 passage.
2. check_evidence accepts it.
3. generate produces a $50 fixture draft with the correct source.
4. check_answer reports claim=False, citation=True.
5. reject_answer publishes a refusal.

The incorrect price first appears in generate. check_answer detects it; it did not introduce the error.

A refusal is an outcome, not a complete diagnosis. Warranty has no retrieved passage. Insurance retrieves a shipping passage but fails the scope gate. Neither reaches generate. For this small application, the scope gate accepts only cost and receipt.

For the stale-reference run, inspect the $5 passage, the $5 draft, and the released $5 answer. Then compare them with the deliberately supplied $7 reference. The mismatch is in the reference. Changing the prompt or weakening check_answer would not fix that expectation.
