1 · Give retrieval a choice

Your previous retrieval function always returned the returns policy. The new Python example has two small document passages. It checks words in the question to choose one.

The example’s tiny document collection
Question wordsPassage
return or returnsUnused items can be returned within 21 days of delivery.
shipping or deliveryStandard shipping takes 3 to 5 business days.

This is a deliberately simple keyword search over passages stored in Python. It has no embeddings, vector database, or language model. Generation still quotes the selected passage with its source.

2 · Follow one question through state

  1. Before retrieval: state contains question: "How long does shipping take?".
  2. Retrieval’s output: the word shipping matches the shipping document. The node returns its passage and source.
  3. Before generation: updated state contains the original question plus the shipping passage and source.
  4. Generation’s output: the answer quotes “3 to 5 business days” and cites the shipping policy.

The graph’s path is still START → retrieve → generate → END. The retrieval function makes the choice inside its node. Nodes read state and return updates; edges determine the next node. Source: Graph API overview.

3 · Predict, run, compare

Use your workspace terminal. For each command, predict the passage before pressing Enter:

.venv-langgraph/bin/python lessons/0004-select-a-passage.py "How long do I have to return an unused item?"
.venv-langgraph/bin/python lessons/0004-select-a-passage.py "How long does shipping take?"
.venv-langgraph/bin/python lessons/0004-select-a-passage.py "What is the warranty?"

The first answer should cite 21 days, the second 3 to 5 business days. The third prints Retrieved passage: (none) and says it could not find a matching passage. That means this search found no match; it does not prove that no warranty policy exists.

How does the Python search work?

lower() makes the question lowercase, strip("?!.") removes those characters from its ends, and split() separates words. A set stores the unique words. The expression words & document["keywords"] finds words shared by the question and the document’s keywords. The first document with a match wins.

Try “How long does shipping take for a return?” Both topics match; the returns document wins because it comes first. “Can I send it back?” finds nothing because these keywords do not include that wording. These limitations are why better retrieval matters.
