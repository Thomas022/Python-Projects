LangGraph + LangSmith · Lesson 11 · 10 minutes

Good evidence can still produce a bad answer

Today’s win: catch a generated price that disagrees with accepted evidence, even when its citation looks correct.

Recall from memory

B with --with-cost retrieved twice in Lesson 10. What did the first passage answer, and why was the second accepted?

Check your answer

The first answered duration. The second supplied the cost per order that B asked for.

1 · Separate the draft from the final answer

Evidence: “Standard shipping costs $5 per order.” Draft: “Standard shipping costs $50 per order. [Shipping policy, section 2]” The evidence fits the question, but generation changed the price. A correct citation does not make that claim supported.

Open the Python example. It keeps Lesson 10’s retrieval loop and question-aware check. Generation now writes draft. A new check_answer node decides whether to release it into answer.

retrieve → check_evidence → generate → check_answer
              ↓ retry                     ↓ accepted: release → END
              ↓ fallback → END            ↓ rejected: reject_answer → END

The retry returns to retrieve. Accepted evidence goes to generate. The graph uses conditional edges for both decisions.

2 · See a citation-only check fail

Predict the final node and price, then run:

.venv-langgraph/bin/python lessons/0011-check-the-answer.py b --with-cost --bad-draft --citation-only
Check after running

Two retrievals → generate → check_answer → release. The final answer says $50. The first wrong step is generate, which changed $5 to $50. The citation-only check then failed to catch that mistake.

3 · Compare the draft with the evidence

For this exercise, we require an exact quotation plus the accepted source citation:

expected = f'{state["passage"]} [{state["source"]}]'
accepted = state["draft"] == expected
return {"answer_ok": accepted, "answer_reason": reason}
A narrow teaching rule.

This equality check rejects valid paraphrases too. It works here because the required answer format is an exact quotation. It does not establish whether the document itself is true or current. No model runs: --bad-draft deliberately simulates a generation error.

4 · Predict, run, compare

Use the default answer check. Predict the final node and whether the draft becomes the final answer.

.venv-langgraph/bin/python lessons/0011-check-the-answer.py b --with-cost
.venv-langgraph/bin/python lessons/0011-check-the-answer.py b --with-cost --bad-draft
.venv-langgraph/bin/python lessons/0011-check-the-answer.py b
Check after running

With cost: two retrievals, then release; the final answer quotes $5 with section 2. With cost and a bad draft: two retrievals, then reject_answer; the $50 draft remains visible for diagnosis, but answer contains a refusal. Without cost: two retrievals, then fallback; generate and check_answer never run.

5 · Follow the state changes

For B with --with-cost --bad-draft:

  1. After the second retrieval: attempts is 2, passage contains $5, and source is section 2.
  2. After check_evidence: evidence_ok becomes True. The accepted passage stays in state.
  3. After generate: draft contains $50 and the section 2 citation. Passage still contains $5; writing draft does not replace passage.
  4. After check_answer: answer_ok becomes False. The router chooses reject_answer.
  5. After reject_answer: answer contains the refusal. Draft remains available to inspect. END stops execution; it is not a node that writes an answer.
Evidence says $5; the draft says $50 with the correct citation. Where is the first wrong step?

There is no generation retry in this lesson. Rejected evidence uses the existing bounded retrieval loop; a rejected draft ends with a refusal.
